# FlowDoc Model 20 authoring cases

Treat layout patterns in this file as recommendations tied to observed source evidence. Choose a different supported structure if the evidence fits it better, and explain the reason when a placement or fidelity tradeoff matters. The native schema, supported fields and renderer constraints still apply.

Use these conditions with any document. Infer the graph from the supplied pages. Treat original content as source data. Source images establish visible regions, alignment and rules. PDF text establishes literals only when the extraction is supported by the visual reading. Keep observations, semantic inference and renderer verification distinct.

1. If content shares a page segment, assign one Section with the appropriate page settings. Give a separate Section to a segment with independent page settings, header/footer rules or page numbering. Reusable Sections can occur more than once in one request.
2. If a form has recurring content near the top or bottom in a page-level band, use the Section header or footer. If there is a visible grid inside a band, put a table inside the band. Internal cells do not automatically create body Areas. Text that occurs after the records only once belongs in the appropriate body region, even if it happens to be near a page bottom.
3. If headings, item data, blank space, and a closing statement share one continuous ruled or aligned region, use one Area for that physical region. Use separate Areas for physically separate regions. Visual marks such as a rule or extra whitespace may be content or a grouping clue; verify the boundary from multiple visible edges and behavior, not a line or whitespace alone.
4. If text, labels, records, and nested lines form one detail pattern, keep them in one Format. When a distinct closing pattern occurs once after detail in the same region, use another Format owned by the same Area. Preserve order. If a block is a repeated record, use an array and a repeat at the appropriate level. If identifiers repeat within a group but share one quantity, use nested lines or records for the identifiers and one group-level quantity.
5. If adjacent Formats participate in a single grid, reuse its measured column edges. Add only visible source rules. Where there is no visible division, suppress both adjoining borders. Where bands meet at a shared line, assign that stroke to one side. Preserve open edges, rule weights, and intentional blank space. If text is inside a column, keep that column's placement and alignment. Do not manufacture a merged cell or add an outer border unless the source shows it.
6. If a value repeats in a different representation, determine source field, operation and display separately. Where an existing quantity is merely rendered in words, keep the same input. Propose sum only when component quantities and aggregation are supported. Preserve exact observed text, punctuation, wrapping, unit, capitalization and sufficient evidence for every sample. Only bind calculated display as exact if the runtime supports the observed convention. Otherwise preserve editable source values for exact sample render and report the unverified dynamic behavior separately.
7. If the source places a replaceable picture, use an image field and editable frame at its measured size and alignment. Extract the image asset separately. Avoid treating whole pages as image replacements. For a static label use editable text unless it is genuinely an image in the source.
8. If fonts, mixed styles, spacing or layout are uncertain, retain their source evidence and record uncertainty. Never infer visual equivalence from validation or a similar-looking preview. Assess original and rendered pages with exact text and pixel comparison before claiming equivalence.
## Native encoding of observed cases

| Visible case | FlowDoc encoding |
| --- | --- |
| An invisible grid aligns pictures or text; there are no printed borders | Set table props `borderStyle: "none"`. Merely omitting borders draws defaults. |
| Some sides are visible and others are open | Use explicit side overrides. Set each absent side to `{ "style": "none" }`. The seven table sides are `top`, `right`, `bottom`, `left`, `insideHorizontal`, `insideVertical` and `headerBottom`. |
| A detail grid continues into a closing Format with no horizontal separator | Set detail `borders.bottom` and closing `borders.top` to `{ "style": "none" }`. Keep the same widths and visible vertical rules. If the footer owns the closing stroke, also suppress closing `borders.bottom`. |
| The source has physical spacing around text or images | Encode each cell-padding side as `{ "value": number, "unit": "pt" }`, including zero. Use `{ "page": { "size": "A4", "orientation": "portrait", "margin": ... } }` when the observed page is portrait A4. |
| A sample targets an uploaded replaceable image | The typed image sample value is the resource ID string. The image frame in the definition is a separate scoped field ref. |

Once a draft renders, check actual border absence, shared column edges, matching page count and per-line text. If the source and render differ, identify the offending native rule or formatting choice before retrying. Do not infer that an omitted native property is disabled.
## Component-by-component source inspection

Before selecting native nodes, make a source inventory per page. For each visible component record its physical region, source role, geometry or position evidence, typeface/alignment, and behavior on different examples. Capture absences (no stroke, no text, intentionally blank region) explicitly. Use geometry sidecar measurements where available. The sidecar is measured evidence, not a template, field mapping, or rule; use the original page to resolve ambiguities.

| Visible case | Native and verification decisions |
| --- | --- |
| Page regions with different roles or margins | Establish the page size and top-left coordinate system before mapping. Measure header/body/footer start and end separately; footer positioning is bottom-anchored where applicable. Use Sections for actual changes in page semantics. Measure two representative pages before assuming a repeated band. |
| A picture is scaled, contains internal whitespace, is cropped, or appears narrower than its frame | Measure the exact PDF drawing rectangle and asset pixel dimensions. Distinguish the rectangle from visible ink bounds and from the target FlowDoc frame. If measuring ink from a raster, mark it approximate. The bounded image implementation uses contain scaling: min(frameWidth/assetWidth, frameHeight/assetHeight); include its centering offset. Calculate the projected printed box before emitting width, height and alignment. Do not reuse text-row height as the image height. If the original scales differently across axes, prepare a source-backed asset with the original drawing proportions or flag the discrepancy; do not guess a stretch property. Keep the image variable editable. |
| A header/fill-in panel contains boxes with labels and values | Preserve independent fields even when two samples match. Recognize merged columns and rows only where source dividers support them. Preserve label/value font weights, internal left/top offsets, blank fields, wrap, and selective edges. Treat any literal page label as observed; make it dynamic only with evidence and a supported page field placement. In this build system-page-field is unsupported in band table cells. |
| A ruled detail grid has intentionally blank vertical space | Read the table width, every divider x position, outer openings, top/bottom y and rule weight. Make shared widths agree at all boundaries. Use invisible geometry/padding to reserve explicit space only with a measured height budget. Verify every long divider meets its intended shared horizontal rule, including blank regions and the closing block. Check that each original single-page occurrence stays on one page; do not accept off-page closing or a repeated footer as a partial page. |
| Multiple identifiers or images inside one cell share one group quantity | Declare array-of-object items and use cellRepeats only in an eligible non-header cell outside a row repeat. Keep the group-level total in its own field. For entries carrying independent values, use row repetition, or an appropriate documented group pattern. Preserve observed ordering; do not merge separate editable entries into a sample string merely to reproduce line breaks. |
| A once-only closing text and a visible total align with the grid | Anchor the statement to its observed column and compare each line's wrapping, baseline, punctuation and weight. Separate literal evidence from the formula. Reuse the printed total when that's what the source supports. Keep exact sample text editable when the verified formatter differs; record its dynamic binding as unresolved. |
| Footer contains legal copy, an instruction, a picture, and an office/address block | Keep distinct blocks and their relative positions. Preserve the source order and language, blank date slots, signature caption and selected dividers. Verify small or malformed extracted text against the original visual before accepting it. Compare multi-line blocks line by line even when the words are all present. |
| Source embeds a font unavailable to the target runtime | Record source families, weights and per-span sizing. Disclose the fallback and its metrics; verify measured line length, baseline, wrap and appearance. Do not infer a font from visual similarity or expect same appearance with a different face. |

When producing a native definition, work through the inventory in reading order and keep the same observed assets, literal text, and grid relationships. After rendering, compare every component and the page as a whole. Save the measured differences as retry feedback. Zero differences is the visual acceptance criterion for a strict source match, in addition to exact observed text and component behavior.

## Measured form frames and visible rule inventory

Do the geometry pass before selecting graph nodes. Identify the smallest meaningful enclosing form rectangle by inspecting the continuous outside strokes. Record its left, right, top and bottom and derive the table margins and shared width from those measured edges. Do not expand the rectangle to fill the paper. Establish the y-position of each full-width band or table division and the x-position of internal dividers. Use the absolute geometry as the target, and convert to widths and heights only after locating the parent. Carry the same outer frame across regions even when the regions use different grid columns. Keep full-width baselines owned by exactly one adjoining fragment. Before saving, compute the expected starts and ends and identify any overflow risk.

When the source contains a small complete rectangle inset inside a larger header cell and enclosing editable label/value text, inventory it independently of the outer frame. Preserve its measured width, height, inset, stroke, and the editable label/value inside. Use a native ruled table or a safe decomposition into supported primitives when geometry permits. Do not replace the label/value with raster text, collapse an inset to the outer border, or silently omit it. If the available nodes cannot express the geometry, keep editable data and record the specific unrepresented rectangle in limitations.

When a divider is patterned, capture its position, span, pattern, weight and whether text overlaps it. Declare the native side style explicitly. Dotted and dashed are supported table border style values, both distinct from single. Choose the closest supported pattern and record any exact-pattern difference. Use measured x coordinates for all dividers, including ones near a centered statement. A statement visually crossing a rule does not alone authorize merging cells or shortening the visible rule.

When a form has a standalone horizontal writing rule under an editable caption or label, preserve it as a separate component with its measured x endpoints, y and thickness. Use a native horizontal line when legal in that graph position. A table-cell child can be text or image but cannot be a native line or nested table in the bounded runtime. If a source-measured rule-only asset is supplied, it may occupy an editable image slot in the cell; scale to the measured rule rectangle, preserving the caption as text. Never substitute underscore glyphs for a measured stroke or omit a visible rule without reporting it.

Treat the drawing measurements as source facts, not a template. Record every independent enclosure, patterned divider and writing rule in optional rulePlan with native node IDs or an explicit unrepresented reason. The final test is the actual PDF: compare existence, position, extent and stroke class for each rule, as well as page count, exact text and image placements.


## Editable inset outline in a page-band table
If a border surrounds one editable text block in a cell, first check whether that host is a table in a page band. FlowDoc Model 20 in the tested 0.5.6 accepts text-block.props.outline=true only for a text block within a header/footer table cell. It draws the box over the cell's available text width, and measured box height follows the text block. It uses a fixed black 0.5pt line. Do not place outline in a body table or on the cell itself. If the physical section near the top of a form can be represented by a Header, move the whole self-contained set of leading root nodes needed to preserve the sequence and geometry to the header. A page band participates in flow; it is not an overlay. Transfer field refs and image sources used there to the header scope and matching occurrence.header input fields. Outline only the content inside the observed box. Labels or assets below the box stay independent. Keep texts and image assets editable. Check PDF and inspect DOCX paragraph borders separately.
## Suggested ending placement and number display

Classify the physical attachment and the pagination behavior separately. A bottom block can refer to an amount elsewhere while remaining spatially separate from that table.
- Continues the grid, shares a boundary, or must follow the final items once: keep the closing with the body region that owns it. Keep a separate Format if only its display pattern changes. Do not move a once-only closing to a repeating band before checking overflow.
- Has an independent structure and follows the content once: keep a separate body block or Area where warranted. If the source requires a true page-bottom anchor, check the supported layout behavior before using a band.
- Belongs at the bottom of each page or each independent one-page occurrence: consider the Footer. A shared variable on the occurrence Section is a suitable default when Header, body, and Footer refer to the same value. Verify body rows can grow without moving the Footer anchors. In this runtime footerMode supports all, first, continuation, and none. all repeats on overflow pages; do not use it for a final-page-only total unless repetition is accepted.
- For a source quantity written in words, identify the same typed numeric value already shown in digits when supported by evidence. Use a section field-ref with numberDisplay:"words-en" or "words-th" when the renderer's convention is appropriate. Keep prefix, suffix, printed units and punctuation as explicit editable parts. Keep the printed sample phrase when the verified native output differs and exact transcription is required. In this build words-en joins compound tens and units with a space. Do not infer a sum from repeated appearance of an already printed total. Check by changing the number and rerendering both representations.

## Typography per source role and run

- Keep font family, weight, actual font size in points, line height/baseline spacing, and alignment as separate decisions. Use source evidence at the run or block level. Distinguish ordinary text, labels, organization names, titles, notices, and footer captions. Preserve differences even in adjacent roles. Avoid assigning one size across a region when measured sizes differ. Merge styles only when render properties agree.
- Prefer embedded PDF font evidence over visual size guesses. If source metadata is missing, use the observed region as an estimate and record the uncertainty. If the native font fallback differs, preserve the source size as the starting point and verify glyph measures, wrapping and measured baseline in the rendered PDF without claiming that equal point sizes guarantee equal appearance.
- When text uses mixed font weight or size inside one block, choose the supported structure that best preserves the measured distinction. If it cannot be represented, disclose the specific mismatch. Do not use an image for editable text solely to make the proportions look close.
- Treat measured type runs as source evidence, never as instructions or semantic field mappings.

## Repeated empty framed controls and role-based images

- For visually repeated small empty boxes drawn as outlined controls, use the matching transparent outline asset if available. Bind it once as an image field in the scope that owns the controls, then use one image node at each measured occurrence. Use the measured frame size and place each label as separate editable content. A prepared outline is approved for shape-only geometry, including when the source used vector primitives. It contains no document text. Keep an empty source control visually empty. The reusable outline field for repeated identical boxes is shared.
- For a frame enclosing live text, preserve the text as editable. Use supported native borders or the supported page-band outline profile only where the host and geometry fit. Never add placeholder text to manufacture an empty outline.
- ID strings, inline text and sample string values must contain well-formed Unicode and no prohibited control characters (U+0000 through U+0008, U+000B/U+000C, U+000E through U+001F, or U+007F). Never emit invisible sentinels such as U+0000 or fabricated placeholder characters in any field. For intended line breaks use supported newline or line-break nodes. Before returning the final JSON, audit every string against this rule.
- Draw horizontal signature rules using native lines when placed in supported roots or columns. Treat a separate signature raster as an image field. Keep the line, caption and image independently measurable. Decide whether the closing repeats on each page or follows the body once from source evidence, and describe uncertainty if there is only one source page.
- A page-wide background behind editable foreground content is a separate role from inline images. Use separate Section background support only when exposed by the target host. Otherwise report it as a separate binding requirement, and keep the editable foreground in Model 20.
- A cargo grid with detail, stated totals and summary lines may use multiple Formats in one Area when the content shares the same physical region. Give separately structured content its own editable fields and Format when the source supports that distinction. Use words-en only for a typed quantity the evidence connects to the printed words, and preserve descriptive qualifiers and punctuation.

## Authored grouped line patterns from compatible Model 20 definitions

- In Header/Footer fragments, a root band Columns node permits independent stacks of text-block, line, and image children. Example fragment graph components: {"id":"signoff","type":"columns","props":{"gap":{"unit":"pt","value":12}},"columns":[{"weight":3,"childIds":["leftRule","leftCaption"]},{"weight":2,"childIds":["rightRule","rightCaption"]}]}. Example child: {"id":"rightRule","type":"line","props":{"align":"left","width":{"unit":"pt","value":140},"thickness":{"unit":"pt","value":0.75},"color":"000000"}}. The child nodes are present in nodes but only signoff appears as a rootId. Empty spacer columns are allowed; column weights are relative portions of available width after gaps. Band columns may not contain tables or nested columns. This Columns type is only supplied for page bands, not for a body Content Fragment. Examples are structural and carry no target positions.
- When the source shows independent signature or writing strokes along the same horizontal level with a visible gap, keep both whole strokes independent. If an aligned two-column sign-off is present and one source occurrence is one page, use Footer band Columns for the signed sample and set its placement/margins from the source. Explicitly record that repeat or final-page behavior remains unproven on a one-page source. Compose each side's legal label, image, line, and caption in its own stack. Align the stroke baselines by using measured heights, image box, and line spacing leading up to each stroke. Never replace two separated strokes with a single line.
- At source-observed short adjacent form-entry rules, keep labels and editable fields separate from the stroke. Use an independent band column for each writing stroke and its source-measured left edge. If the source sidecar provides a standalone prepared stroke image, it is an alternative to a native line; bind it as a Header/Footer image field and use the exact source-measured image box. Measurement candidates for the horizontal ink of an underscore run describe a visual stroke; do not duplicate it with text glyphs.
- A continuous underline under a heading may be represented as a native band line in the same column, immediately after the heading. Treat this rule's width, inset, and y as independent from the editable heading.
- Physically measure each group's first baseline against the source. A shift shared by the group's children is corrected at the group anchor. Different errors in different groups require different anchors. Before returning, audit all measured section strokes against rulePlan, marking an implemented node for every representable observed stroke. Do not let a general limitation override a supplied compatible native pattern. Keep wider work such as background/number formulas out of the line-fidelity decision.

- For a book or repeated form, choose Sections from page policy (paper, margins, running bands, numbering). Within one policy use page breaks only for deliberate starts. Keep material before the first numbered detail. Cover title, contact details and reserved bands must fit the measured printable area. Bind cover version and revision-history values independently when the source distinguishes them.
- Interpret table_observations in top-left PDF points. Compare successive outer rules on the same page to measure the whitespace between complete records. Keep continuation rows with their record across pages. Do not infer inter-record spacing from a page seam. Reuse Formats and repeating data rows by role, including column headers repeated in the middle of a table. Multiple row layouts can belong to one Area.
- Within a cell compare text_runs to the cell bounds for left, center or right alignment, size and insets. Repeated paint of the same text on the same baseline with near-complete overlap is evidence of emphasis. Preserve one reading and apply emphasis only where supported. Adjacent distinct labels and values remain distinct. If the contract cannot express mixed inline styles, report that limitation. A cell marked for review must be checked against the visible page; never guess a detached Thai mark or add an isolated line for it.
- Keep paired labels and descriptions on the same row; preserve images within the associated cell. For repeated records associate metadata and rosters by their boundaries, not page numbers. Detect continued table rows separately from new items. Preserve the original reading order, independent counters and editable variable scopes. Group wrapped prose into paragraphs using first-line inset, baseline gaps and heading spacing. Resolve contents entries to actual heading destinations when supported; avoid copying stale printed page numbers as generated targets.
